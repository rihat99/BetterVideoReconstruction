## 4. Known differences and open items
- BEDLAM2 `label_bedlam2 --step forces` (kindyn warm start) main vs dev on CPU: max 15–21 N on forces up to 390 N, mean 0.04–0.07 N, base-wrench RMS 26.28→26.27 / 35.57→35.48 N (review_R.md). Same class as the kindyn_1 chain differences; `FORCE_METHOD` not bumped.
  Why (investigation F, artifacts/force_diff/report_F.md, scene 00000000): the inputs the two stacks hand the force solve differ only by BetterRobot's FK/RNEA/Jacobian rounding (≤1.4e-6 relative) plus the order the loss weight is multiplied in (last bit). Both stacks minimise the same objective (1.2e-7 relative at the same point), and that objective has a single stable optimum (main's and dev's inputs give optima 3e-4 N apart). The shipped solver never reaches it: softplus-parametrised L-BFGS stops at its 200-iteration cap 1.55 % above the optimum, 10.9 N median / 61 N max from the optimal forces, almost all of it along slowly varying internal "squeeze" forces between two contacts of one foot or between the sit points (Hessian floor ≈ 2·w_force_magnitude, condition number 3.8e4), and the softplus freezes ~1100 activations at exactly 0 in float32 (540 of them want to come back). Where such an unfinished run stops is chaotic in last-bit changes: 1e-7 input noise, the weight order alone, or 4 vs 12 CPU threads each move the forces by 3–37 N max / 0.1–0.5 N median, and the main→dev gap (16.1 N max, 0.31 N median) is one draw from that band. The BR optim wiring itself contributes exactly 0 (bit-identical when the weight order is patched back). Solving λ ≥ 0 as bounded variables to convergence makes main and dev agree to 3e-4 N but relabels the dataset (forces move 10.9 N median, mean Σ|f| 717.5→707.8 N vs body weight 707.5 N) and is ~15× slower; kept as a possible follow-up, not done.
- kinematics_1 slowdown vs main (above) — profile BH dev body load + HumanState memoisation.
- L-BFGS phases log one line per phase (BR's closure is private); a BR `TorchOptim(on_closure=)` hook would restore the every-5th-closure lines.
- Leftovers for the user: `/tmp/bvr_view_*` symlink farms from viewer checks (trash refuses /tmp); scratchpad venv `s6/venv_c` (5 GB); `data_dev` (reference runs, ~2 GB) can go when the branch is accepted.
